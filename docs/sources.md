# Microsoft sources and evidence

| Claim | Microsoft source | Demo evidence required |
|-------|------------------|------------------------|
| Generic connector OAuth does not support client credentials | [Connection parameters](https://learn.microsoft.com/connectors/custom-connectors/connection-parameters) | Documented restriction; do not fabricate a failed supported grant |
| Connector Managed identity remains user-delegated; cross-environment import creates new federation identity | [Entra connector authentication](https://learn.microsoft.com/connectors/custom-connectors/azure-active-directory-authentication#managed-identity-authentication) | Configured source/target identities and real target Connection |
| APIM export supports subscription parameter plus OAuth | [Export APIs to Power Platform](https://learn.microsoft.com/azure/api-management/export-api-power-platform) | Live connector requires both JWT and key |
| Connector request policies can inject a Connection parameter into a header | [Set HTTP Header policy](https://learn.microsoft.com/connectors/custom-connectors/policy-templates/setheader/setheader) | Secure subscription-key parameter and request policy, then real flow run |
| APIM can authorize a delegated caller | [Validate Entra token policy](https://learn.microsoft.com/azure/api-management/validate-azure-ad-token-policy) | Policy plus real rejection cases |
| APIM uses application identity for backend authentication | [Managed identity policy](https://learn.microsoft.com/azure/api-management/authentication-managed-identity-policy) | Backend response with exact APIM identity checks and required role |
| OAuth secrets are not stored in Dataverse connector records | [Solution custom connector APIs](https://learn.microsoft.com/connectors/custom-connectors/solution-custom-api) | No credentials in definitions or deployment artifacts |
| Connector environment variables require save-time reevaluation | [Connector environment variables](https://learn.microsoft.com/connectors/custom-connectors/environment-variables) | Documented behavior; not a live proof unless tested |
| Connection References bind environment-local Connections | [Connection References](https://learn.microsoft.com/power-apps/maker/data-platform/create-connection-reference) | Real managed consumer flow before/after connector update |
| SP flow ownership is distinct from connector authentication | [Service principal flow support](https://learn.microsoft.com/power-automate/service-principal-support) | Documented distinction; ownership is not app-only connector proof |
| Power Platform Build Tools support automated ALM | [Azure DevOps Build Tools](https://learn.microsoft.com/power-platform/alm/devops-build-tools) | YAML template; live pipeline only if actually executed |

## Evidence status

Twenty local authorization, HTTP and connector-contract tests pass. Azure APIM Developer and Linux B1 backend are deployed in approved Sweden Central; backend health reports ready. Six live rejection cases pass: missing subscription key, invalid key, missing bearer, malformed bearer, real wrong-audience bearer, and anonymous direct-backend request. Deployed identity inspection confirms the APIM backend application-role assignment, v2 tokens, optional `idtyp` configuration and no connector client secrets. These checks do not replace a successful real connector flow.

The user explicitly approved European Union & EFTA including Switzerland. Both isolated Developer environments are ready with Dataverse (Build: Switzerland North; target: Switzerland West). The source connector uses Managed identity federation, and the managed connector solution is imported into target with a distinct registered federation subject/redirect. Initial security correction version `1.0.0.1` restores the required subscription-key parameter after the Security UI removed it; downloaded OAuth metadata is preserved. The separate consumer flow/reference has been authored and exported.

**Real baseline verified:** the user repaired the existing delegated Connection in their ordinary browser. The managed consumer was imported with that Connection and activated. Run `08584077183106224027230767590CU28` succeeded; `GetProof` returned HTTP 200, exact APIM object/client identity checks true, required `Demo.Invoke`, and no delegated scope or user-context claims. Evidence: ignored `out\baseline-run.local.json`. This verifies the actual identity boundary, not just a Connection's Connected label.

**Compatible update verified:** managed connector solution changed `1.0.0.1` -> `1.0.1.0`, and the effective definition changed `1.0.0` -> `1.0.1`, not just the solution version. The corrected consumer is `1.0.1.0`. The same Connection `a70df4ce-b90d-43c4-9f07-5119-03bc0036` and reference `616ee0b0-092b-4313-9a4a-443ba727ec62` survived. Run `08584077153898941665765164881CU11` succeeded at 16:11:35-16:11:36 +01 on 2026-11-05, with HTTP 200 and the same exact APIM application identity checks. No Reconnect or reauthentication occurred between baseline and this run.

This required a guarded repair, not a blind import. Solution Layers exposed duplicate consumer connector ownership and a masking Active unmanaged layer. The consumer upgrade removed duplicate ownership. After separately approved removal of the single connector's Active customization, the new managed definition became effective but exposed Build's OAuth redirect/federation subject. The security guard stopped execution. The user then approved restoring the original target-only metadata. Full target OAuth/key parameter SHA256 returned exactly to its baseline; the header policy wrapper changed Pascal/camel case, but its normalized complete policy/parameters SHA256 matches baseline. Target Entra federation/redirect remained independently verified with zero client secrets. These findings limit the automation claim; the reproducible repair is documented in the deployment guide.

These local files are ignored, not published.

Wrong-role, wrong-client/identity and user-context rejection are unit-tested, not live negative-token cases. APIM scope requirements are structurally checked; a real wrong-scope token case has not been executed. Catalog, environment-variable save-time reevaluation, canvas/Dynamics integration and Azure DevOps execution remain documented possibilities, not demonstrated results.

Do not interpret the pipeline template, a managed package export, or a direct HTTP response as proof that a real Power Platform flow and its existing Connection survive a connector update. Persist the actual observed results before marking those claims proven.
